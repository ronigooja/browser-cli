# Production browser acceptance

Use the current Chrome extension and matching signed Safari companion from the [production setup](../README.md#register-the-server) in an explicitly consented disposable GUI session. Run Chrome and Safari tracks independently in separate test users or desktops; do not overlap them in the same GUI session because capture and qualification both depend on foreground identity. The unsigned macOS workflow and Linux fixtures are not live evidence.

- **Capture (both browsers):** serve `tests/fixtures/capture.html` from loopback (`python3 -m http.server --bind 127.0.0.1 --directory tests/fixtures 8765` in the consented test session). Confirm the exact regular HTTP tab, wait for `body[data-ready=true]`, and capture the viewport and `#crop`. Verify dimensions and the red then blue interior against the visible CSS rectangle at standard and Retina scales. Use a wide window so the seeded canvas forces chunking. Loss of focus, selection, or document during capture must not return a wrong or partial image; an inactive target must not be activated. Verify Chrome reads without the optional screenshot grant, then grant it using the extension toolbar once and capture twice. Check a separately authorized, already-open signed-in fixture; stop at human verification and keep captured pixels private.
- **Uninstall (disposable GUI user only):** explicitly approve Chrome self-removal; verify its result in every affected profile independently, and then approve Trash cleanup. Safari browser removal is manual; with a trusted configured Team ID, verify cleanup of a remaining default signed companion and retention on the wrong Team ID or a custom path. Check that browser profiles and application group data are unchanged. Never interpret a disconnect as removal.
- **Safari zero-window:** use the signed production companion. Pass read-only status and find with a test window as controls; close every Safari window without quitting, leave another app frontmost, then repeat immediately and after idle. Test quit separately: no API call may relaunch Safari. Use the separately authorized production qualification only after the named profile is armed. Independently verify the resulting window is in the intended profile, and review foreground continuity including transient changes. Neither an accepted request nor a candidate result is proof. Do not repeat a possibly committed attempt, or automatically close its fixture window. Production regular background reads retain their zero-window refusal until this behavior is qualified.
